**Завдання 2.2:** Продажі за регіонами з використанням HAVING

```sql
-- SUM, GROUP BY, HAVING

SELECT 
    regions.region_name,
    SUM(order_items.quantity * order_items.unit_price) AS total_sales
FROM regions
INNER JOIN customers ON regions.region_id = customers.region_id
INNER JOIN orders ON customers.customer_id = orders.customer_id
INNER JOIN order_items ON orders.order_id = order_items.order_id
GROUP BY regions.region_name
HAVING SUM(order_items.quantity * order_items.unit_price) > 5000
ORDER BY total_sales DESC;

**Результат виконання:**
```
-- Результат

| region_name              | total_sales |
| ------------------------ | ----------- |
| Дніпропетровська область | 1049967.00  |
| м. Київ                  | 1024367.00  |
| Харківська область       | 362084.00   |
| Одеська область          | 91996.00    |
| Львівська область        | 64587.00    |

Пояснення:
Цей запит призначений для аналізу та обчислення загальної суми продажів у розрізі регіонів.

З'єднання таблиць (INNER JOIN): Запит послідовно об'єднує чотири реляційні таблиці — regions (регіони), customers (клієнти), orders (замовлення) та order_items (позиції замовлень), щоб зв'язати кожен окремий товарний чек із конкретним географічним регіоном.

Агрегатна функція (SUM): Використовує множення кількості товару на його ціну (order_items.quantity * order_items.unit_price), після чого сумує ці значення для кожного регіону через функцію SUM(...), створюючи загальний показник продажів під назвою total_sales.

Групування (GROUP BY): Конструкція GROUP BY regions.region_name збирає всі дані в групи окремо за назвою кожного регіону.

Фільтрація (HAVING): Оператор HAVING застосовується для фільтрації вже згрупованих даних (на відміну від WHERE, який фільтрує окремі рядки до групування). У цьому випадку умова HAVING SUM(...) > 5000 залишає у фінальному звіті лише ті регіони, де загальна сума продажів перевищує 5000 одиниць.

Сортування (ORDER BY): Наприкінці результати сортуються за зменшенням (DESC), завдяки чому регіони з найбільшими обсягами продажів автоматично опиняються нагорі списку.

**Завдання 2.3:** Постачальники з кількістю товарів більше 2

SELECT

RANK() — присвоює однаковий ранг товарам із рівними цінами, але робить «пропуски» у номерах (якщо два товари поділили 1-е місце, наступний отримає 3-є).

DENSE_RANK() — також дає однаковий ранг товарам з однаковою ціною, але не робить пропусків у нумерації (після 1-го місця одразу йде 2-е).

ROW_NUMBER() — гарантує унікальний порядковий номер (1, 2, 3...) для кожного рядка у вікні, навіть якщо ціни у товарів повністю збігаються.

З'єднання та сортування: Таблиця товарів (products) з'єднується з таблицею категорій (categories) за допомогою INNER JOIN, а фінальний результат упорядковується за назвою категорії та спаданням ціни товару.
